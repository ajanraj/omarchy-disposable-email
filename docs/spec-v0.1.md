# Disposable Email v0.1

## Product

Publish an Omarchy Quattro plugin named Disposable Email with ID `io.github.ajanraj.disposable-email`, version `0.1.0`, and an MIT license. One bar icon opens one native Omarchy panel with three remembered tabs: Temporary, DuckDuckGo, and SimpleLogin.

## Temporary

- Support Maildrop and Harakiri, with Maildrop as the first-run default.
- Generate a UUID local part, copy the address, and open the provider-hosted public inbox.
- Remember one current address across shell restarts.
- Provide Copy, Open Inbox, Replace, and Forget.
- Confirm Replace and Forget. Neither action deletes the provider inbox.
- State clearly that the inbox is public.
- Do not embed messages or add Mail.tm in v0.1.

## DuckDuckGo

- Accept a user-extracted bearer token and store it through Secret Service.
- State clearly that the integration is unofficial and may break.
- Generate and copy a private Duck address.
- Persist only aliases generated by this plugin, labelled as Known Duck Aliases.
- Query current active status and allow confirmed deactivation or immediate reactivation.
- Allow local Forget without claiming remote deletion.
- Do not claim complete inventory, deletion, activity, or statistics support.
- Preserve local history and disable unavailable remote actions when the unofficial API breaks.

## SimpleLogin

- Accept a user-created API key and store it through Secret Service.
- Create and copy random aliases with the note `Created with Disposable Email`.
- Create custom aliases with prefix, suffix, verified destination mailboxes, display name, and note.
- Search and paginate aliases, filter by all, enabled, disabled, or pinned, and show destination mailbox, enabled state, pinned state, and forwarding counters.
- Copy, pin or unpin, and enable or disable aliases. Confirm disable.
- Do not expose alias deletion in v0.1.
- Retain the last successful alias data on failure, mark it stale, and provide retry.
- Surface provider plan limits without automatic retry.

## State and security

- Use a singleton Quickshell service as the shared state owner across monitors, with no background polling.
- Keep Temporary, DuckDuckGo, and SimpleLogin as provider-specific modules.
- Persist only last tab, temporary provider, current temporary address, and Known Duck Aliases under XDG state.
- Store no credential in the repository, manifest, shell settings, state, environment, process arguments, temporary files, or logs.
- Use Secret Service through `secret-tool`. Write credential values through stdin without a trailing newline.
- Pass HTTP authorization to curl through stdin with static argv and hard timeouts.
- Fetch remote data only when the user opens the relevant view, refreshes, or performs an action.
- On an invalid credential, retain it, mark the provider as needing attention, and offer replacement or disconnect.
- Disconnect clears that provider's local credential and cached data. Reset clears all plugin state and credentials but never mutates remote aliases.

## UX and publishing

- Follow native Omarchy styling and keyboard behavior, including Escape dismissal and visible focus states.
- Use generic icons and provider names, not bundled provider logos.
- Show concise busy, failure, stale, and privacy states.
- Document dependencies, credential setup, public inbox risk, unofficial API risk, state locations, Secret Service caveats, removal behavior, manual cleanup, limitations, and validation commands.
- Do not rely on an uninstall hook. Omarchy removal leaves XDG state, Secret Service credentials, inboxes, and aliases untouched unless the user resets first.

## Acceptance

- `omarchy plugin validate` passes.
- Every QML file passes `qmllint` against the installed Omarchy shell imports.
- Focused state and provider parsing tests pass without live credentials.
- No symlinks, secrets, or em dashes exist in the published plugin tree.
- Live DuckDuckGo and SimpleLogin verification is a separate local pass using user-owned credentials before marketplace submission.
